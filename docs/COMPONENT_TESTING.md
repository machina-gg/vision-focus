# コンポーネントテストの方針

React コンポーネントの単体テスト（Vitest + Testing Library）をどう書くかの決まり。
E2E テストケースの一覧は [TEST_CASES.md](./TEST_CASES.md) が持つ。

## なぜ書くか

過去に出た表示の不具合は、いずれも**表示の出し分け**だった
（ロゴが出ない・ポップアップに目標が出ない・URL 入力欄が短い・YouTube の非表示が効かない）。
E2E は値を設定してから画面を確認するため、**未設定のまま開いた経路**を踏んでいない。
コンポーネントテストはこの穴を埋めるために置く。

## 何を確かめるか

次の 2 つだけを見る。

1. **与えた値で何が表示されるか** — 未設定（`undefined` / `null`）・空文字・空白のみ・0 件・
   境界の値を含める。「設定済みで正しく出る」よりも「**未設定で壊れない**」を優先する
2. **操作したときに何が呼ばれるか** — コールバックが呼ばれたことだけでなく、
   **渡る引数**まで見る（どのドメインが削除されるか、どの解像度で保存されるか等）

⚠ **実装の不具合を見つけても、その挙動をテストで固定しない。**
誤った表示を「仕様」にしてしまうため、その場合は「例外にならない」「次の段階へ進まない」ことだけを
検査し、不具合は Issue に起票する。

## 何を確かめないか

- **見た目のスナップショットを取らない。** マークアップを書き写したテストは、
  壊れていなくてもクラス名や要素の並びを変えただけで落ちる。落ちる理由が
  「壊れた」なのか「書き換えた」なのか区別が付かなくなり、更新するだけの作業が増える
- **装飾のためのクラス名は見ない**（例外を置かない）。状態の差が装飾でしか表現されていないなら、
  **実装側に状態を表す属性を足してから検査する**。詳しくは下記「状態は属性で表す」
- **E2E で見るもの（画面をまたぐ遷移・拡張機能 API の実挙動）は扱わない**

## 置き場所

テストは対象コンポーネントと同じ階層の `__tests__/` に、`<コンポーネント名>.test.tsx` で置く。

```
src/components/options/
├── WeeklyCalendar.tsx
└── __tests__/
    └── WeeklyCalendar.test.tsx
```

- **同じ階層に置く**のは、対象を移動・削除したときにテストの置き忘れが起きないため
- **`__tests__/` にまとめる**のは、`vitest.config.ts` のカバレッジ設定が
  `src/**/__tests__/**` を集計対象から外しているため。ディレクトリ名がそのまま除外条件になる
- テストから実装は `../<コンポーネント名>` で参照する。それ以外のモジュールは `~/` 別名を使う

## 状態は属性で表す

色・太さ・枠線だけで状態を表している画面は、**読み上げ利用者にその状態が伝わっていない**。
クラス名を見るテストは、この欠陥をテスト側で肩代わりして隠してしまう。
そのため**状態はコンポーネント自身に属性として持たせ、テストはその属性を見る**。

属性の選び方は次の 1 つの流儀に揃える。

| 表したいこと                             | 使う属性                                  |
| ---------------------------------------- | ----------------------------------------- |
| 選択中かどうか（切り替えボタン）         | `aria-pressed`                            |
| 操作できないこと                         | `disabled`（スタイルだけで止めない）      |
| アイコンだけのボタンの名前               | `aria-label`（文言は `messages.json` へ） |
| 上記以外の内部状態・見た目の種類や大きさ | `data-<プロパティ名のケバブケース>`       |

- `data-*` には**プロパティの値をそのまま**入れる（真偽値は `"true"` / `"false"` の文字列）。
  属性の有無ではなく値で表すのは、「偽である」ことも検査できるようにするため
- **見た目は変えない。** クラス名の当て方はそのままにして、属性を足すだけにする
- 例: `<Button data-variant="ghost" data-size="sm" data-loading="false">`

⚠ アイコンを `lucide-<アイコン名>` で特定するのは要素の特定であって状態の検査ではない。
ただし**状態をアイコンに寄せたまま残っている箇所がある**
（測り方: `git grep -n "lucide-" -- 'src/**/__tests__/**'`）。その画面を触るときに上の表へ揃える。

## 書き方の決まり

- **実装を変えるのは、状態が属性として出ていないときだけ**（上記「状態は属性で表す」）。
  要素を取るためだけに `data-testid` を足す前に、役割（`getByRole`）・文言（`getByText`）・
  `aria-label` で取れないかを先に試す
- **文言はキー名で検査する。** テスト環境に `chrome.i18n` は無く、`getMessage` はキー名を返す
  （`src/lib/i18n.ts`）。置換値（件数・分数・ドメイン名）が表示に出ているかを見たいときは
  `src/test/i18n.ts` の `stubI18nWithSubstitutions()` を呼ぶと `キー名(置換値)` の形で描画される
- **外部に任せている処理は差し替える。** ストレージ・ハッシュ化・画像圧縮・CSV 書き出しなどは
  `vi.mock` で置き換え、「**失敗したときに次の段階へ進まない**」ことを検査する
- **現在時刻に依存する表示は時刻を固定する。** `vi.useFakeTimers()` + `vi.setSystemTime()` を使う
- **`describe` は状態ごとに分ける**（「〜のとき」「〜モード」）。`it` は日本語で
  「何が起きるか」を書く

## 壊したら落ちることを確かめる

数を揃えただけで実際には何も守っていないテストになっていないか、波ごとに実測する。
実装を 1 箇所だけわざと壊し、**狙ったテストが落ちること**を確認してから元へ戻す
（壊した状態はコミットしない）。落ちなければ、そのテストは検査になっていないので書き直す。

## カバレッジ

閾値は `vitest.config.ts` が持つ。**退行防止のための下限値**であり、
テストを増やしたその PR で引き上げることはしない（引き上げは別途判断する）。
測り方は [README.md](../README.md) の「カバレッジ」を参照。
